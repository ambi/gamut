# 変異体の判定に、テストプロセスを使い回す

## 動機

変異体ごとに新しいテストプロセスを起動すると、パッケージの初期化（テストファイルのパッケージ変数を含む）を変異体の数だけ繰り返す。
idmagic の `backend/oauth2/internal/token/usecases` のテストは、パッケージ変数の初期化で RSA の鍵を 2 つ作るので、プロセス 1 つの起動に 0.1〜0.18 秒かかる。
463 体の実行の大半は、この初期化だった。

## 対象範囲

- overlay で判定のテスト（`TestGamutServer`）を足し、1 つのテストプロセスで変異体を順に判定する。プロセスは gamut の 1 回の実行の間だけ動く。
- 変異体がプロセスの状態を汚したかを確かめ、汚れていれば、プロセスを捨てて新しいプロセスで判定し直す。
- 被覆の記録に使ったプロセスを、そのまま判定に使い回す。
- `-isolate` で、変異体ごとにプロセスを分ける従来の方式を選べるようにする。

## 対象外

- 逆依存パッケージのテストバイナリでの使い回し。判定のテストはパッケージ自身のテストバイナリにだけ足す。
- 実行の間をまたいで常駐するプロセス（保存のたびの再実行は [027](027-watch-mode.md) で扱う）。

## 設計

判定のテストは、標準入力から「変異体の番号 テスト名...」の行を受け取り、選択を切り替え、テストを `t.Run` で順に呼ぶ。
結果はファイル記述子 3 に書く。テストの出力と混ざらないためである。
変異体を検出したら、検出したテストを変異なしでもう一度実行する。
通らなければ、前の変異体か今の変異体がプロセスの状態を汚したので、プロセスを捨て、今の変異体を新しいプロセスで判定し直す。
プロセスが落ちたとき（`panic`、`os.Exit`）と時間切れのときも、プロセスを捨てる。

## 完了の条件

- 固定モジュール（時間切れ、`panic`、`t.Parallel` を含む）で、使い回した判定が、変異体ごとのプロセスでの判定と一致する。
- 被覆の記録をまとめる 2 つの方法（判定のテストのプロセスと、`-isolate` のときの go test の 1 回の実行）が、1 件ずつの測定と同じ判定を生む。
- idmagic の `usecases` の初回で、使い回さない方式より短い。

## 検証

- `TestAll_ServedVerdictsMatchOneProcessPerMutant` と `TestAll_BatchedCoverageMatchesOneProcessPerTest`。
- idmagic での測定。

## 要約

- `schemata.BuildServer` が判定のテストを作る。外部テストのパッケージに置き、内部テストは対象パッケージから公開した関数として、外部テストはそのまま呼ぶ。main パッケージは外部テストから import できないので内部テストのパッケージに置き、外部テストもあれば使い回さない。
- 各テストは `t.Run("g", func(t) { t.Run(name, fn) })` で呼ぶ。外側の `t.Run` は並列のサブテストが終わるまで戻らないので、`t.Parallel` のテストも次の変異体へ持ち越さない。
- 判定のテストは「cover テスト名...」の命令も受け付け、変異なしでテストを順に実行して被覆を記録し、テストごとの所要時間を返し、最後に記録を止める（`GamutCoverStop`）。被覆の記録をまとめて測ったプロセスを、そのまま判定に使う。
- 汚れの確認は、変異体を検出したときだけ行う。生き残ったときの汚れは、次に検出した変異体の確認で見つかり、その変異体を新しいプロセスで判定し直す。生き残りの判定が汚れた状態から出た可能性は残るが、汚れはテストを失敗させる向きに働くことが多い（検出の誤り）ので、確認は検出の側に置いた。
- idmagic の `usecases`（562 体）の初回は、変異体ごとのプロセスで 36.5 秒、使い回して 6.5 秒だった。判定は使い回さない方式と一致した。
- `-isolate` は、テストがプロセスの状態に強く依存し、汚れの確認で捉えられない場合のために残した。
