# gamut の設計：変異体

この文書は、変異演算子、変異体の識別子、arid のコード、無効化コメント、等価な変異体の受理と自動検出を定める。
全体の目的とロードマップは [設計の概要](README.md) が定める。

## 変異演算子

| 名前 | 対象 | 置き換え |
| --- | --- | --- |
| `ARITHMETIC_BASE` | 二項の `+`、`-`、`*`、`/`、`%` | `+`↔`-`、`*`↔`/`、`%`→`*` |
| `CONDITIONALS_BOUNDARY` | `<`、`<=`、`>`、`>=` | `<`↔`<=`、`>`↔`>=` |
| `CONDITIONALS_NEGATION` | `==`、`!=`、`<`、`<=`、`>`、`>=` | `==`↔`!=`、`<`↔`>=`、`>`↔`<=` |
| `INCREMENT_DECREMENT` | `++`、`--` の文 | `++`↔`--` |
| `INVERT_NEGATIVES` | 単項の `-` | `+` |
| `INVERT_BITWISE`（既定で無効） | 二項の `&`、`\|`、`^`、`&^`、`<<`、`>>` | `&`↔`\|`、`^`→`&`、`&^`→`&`、`<<`↔`>>` |
| `INVERT_ASSIGNMENTS`（既定で無効） | 複合代入の `+=`、`-=`、`*=`、`/=`、`%=` | `+=`↔`-=`、`*=`↔`/=`、`%=`→`*=` |
| `INVERT_BITWISE_ASSIGNMENTS`（既定で無効） | 複合代入の `&=`、`\|=`、`^=`、`&^=`、`<<=`、`>>=` | `&=`↔`\|=`、`^=`→`&=`、`&^=`→`&=`、`<<=`↔`>>=` |
| `INVERT_LOOP_CTRL`（既定で無効） | `break`、`continue` の文（ラベル付きを含む） | `break`↔`continue` |
| `INVERT_LOGICAL`（既定で無効） | `&&`、`\|\|` | `&&`↔`\|\|` |
| `REMOVE_LOGICAL_NOT`（既定で無効） | 単項の `!` | 取り除く（`!x`→`x`） |
| `BOOLEAN_LITERAL`（既定で無効） | 宇宙スコープの `true`、`false` | `true`↔`false` |
| `RETURN_ZERO` | 戻り値を持つ関数の本体（`init` を除く） | 先頭で戻り値の型のゼロ値（`error` は `nil`）を返す |
| `STATEMENT_REMOVE` | 値を返さない呼び出しの文（ログ出力を除く） | 実行しない（`f(x)`→`if false { f(x) }`） |
| `CONDITIONS_CONSTANT`（既定で無効） | `if` と `for` の条件、`&&` と `\|\|` の被演算子（定数の式を除く） | `if`：`true` と `false`。`for`：`false`。`&&` の被演算子：`true`。`\|\|` の被演算子：`false` |
| `REMOVE_SELF_ASSIGNMENTS`（既定で無効） | 複合代入の `op=` すべて | `=` にする（`x += y`→`x = y`） |
| `INTEGER_INCREMENT`、`INTEGER_DECREMENT`（既定で無効） | 整数のリテラル（`make` の容量と `map` の大きさの見込みを除く） | 1 増やす、1 減らす。10 進で書き、負なら括弧で囲む（`0`→`(-1)`） |
| `FLOAT_INCREMENT`、`FLOAT_DECREMENT`（既定で無効） | 浮動小数点数のリテラル | 1 増やす、1 減らす。小数点か指数を必ず含める（`1e2`→`101.0`） |
| `BRANCH_IF`、`BRANCH_ELSE`、`BRANCH_CASE`（既定で無効） | `if`、`else`（`else if` を除く）、`switch` の `case` の空でない本体（`fallthrough` で終わるものと、中身がすべて arid のものを除く） | 本体を実行しない（`{ f() }`→`{ if false { f() } }`） |
| `ERRORF_WRAP`（既定で無効） | `fmt.Errorf` の書式のリテラルの `%w` | すべて `%v` にする（`%%` は動詞でないので変えない） |
| `RETURN_ERROR_NIL`（既定で無効） | `return` の結果のうち、囲む関数の結果の型が `error` で、`nil` でない式 | `nil` を返す |

名前と置き換えは Gremlins と gomutants に合わせる。
各演算子の説明と例は `internal/mutant` の 1 か所（`mutant.Infos`）で定め、`-list-mutators` はそこから出す。手引き（`docs/guide/configuration.md`）の一覧が全演算子の名前を挙げることは、テストで確かめる。
`-disable` は既定の集合から演算子を外す。`-only` とは併用できない（終了コード 1）。
既定で無効な演算子は、`-only`（設定の `mutators`）で選んだときだけ列挙する。実在のパッケージで生き残りの数と仕分けの内訳を測ってから、既定の集合に入れるかを決める。

### 既定の集合

既定の集合は、表の「既定で無効」の付かない 7 つである。
2026-11-21、idmagic の `backend/oauth2/internal/token/usecases` で、既定で無効だった 10 演算子をすべて選んで測った。

| 演算子 | 変異体 | 検出 | not detected | not infected | not covered | 構築不能 |
| --- | --- | --- | --- | --- | --- | --- |
| `CONDITIONS_CONSTANT` | 1,299 | 639 | 77 | 256 | 156 | 171 |
| `INVERT_LOGICAL` | 151 | 88 | 41 | 0 | 22 | 0 |
| `RETURN_ZERO` | 85 | 63 | 7 | 0 | 15 | 0 |
| `REMOVE_LOGICAL_NOT` | 76 | 63 | 1 | 0 | 12 | 0 |
| `BOOLEAN_LITERAL` | 71 | 33 | 7 | 0 | 31 | 0 |
| `STATEMENT_REMOVE` | 41 | 18 | 9 | 0 | 14 | 0 |
| `INVERT_LOOP_CTRL` | 12 | 1 | 3 | 0 | 8 | 0 |
| `INVERT_BITWISE` | 2 | 0 | 2 | 0 | 0 | 0 |

複合代入の 2 つは、このパッケージに箇所がなかった。

- `RETURN_ZERO` と `STATEMENT_REMOVE` を既定に入れた。生き残りは、結果を確かめていない関数と、確かめていない副作用（監査イベントの発行など）で、どれもテストの穴だった。既定の集合の時間は 5.0 秒から 5.4〜6.2 秒、変異体は 562 体から 688 体になった。
- `CONDITIONS_CONSTANT` は既定に入れない。変異体が既定の集合の 2 倍を超え、`not infected` の 3 分の 1 は `err != nil -> false`（エラーの経路を通るテストがない）で、ほかの演算子の `not covered` と重なる。条件でだけ使う変数が使われなくなる構築不能も多い。
- `INVERT_LOGICAL` は、生き残りが 27% と多く、1 体ずつの見極めが要るので、既定に入れない。
- ほかは、箇所が少ないか生き残りがほとんどなく、既定の時間を延ばすほどの情報を足さないので、既定に入れない。

2026-11-21、同じパッケージで、数値のリテラル、分岐の本体、エラーの包みを変える 10 演算子を選んで測った（`-no-cache`、12.6 秒）。

| 演算子 | 変異体 | 検出 | not detected | not infected | not covered | 構築不能 |
| --- | --- | --- | --- | --- | --- | --- |
| `BRANCH_IF` | 498 | 240 | 27 | 0 | 231 | 0 |
| `RETURN_ERROR_NIL` | 239 | 78 | 1 | 10 | 150 | 0 |
| `INTEGER_INCREMENT` | 62 | 30 | 23 | 0 | 9 | 0 |
| `INTEGER_DECREMENT` | 62 | 22 | 24 | 0 | 7 | 9 |
| `BRANCH_CASE` | 31 | 15 | 3 | 0 | 10 | 3 |
| `BRANCH_ELSE` | 4 | 3 | 0 | 0 | 1 | 0 |
| `ERRORF_WRAP` | 1 | 0 | 1 | 0 | 0 | 0 |

`REMOVE_SELF_ASSIGNMENTS` と `FLOAT_*` は、このパッケージに箇所がなかった。
`ERRORF_WRAP` は箇所が少ないので、`%w` の多い 5 パッケージ（`shared/http/support_http`、`accesscontrol/internal/domain`、`saml/domain`、`oauth2/internal/logout/usecases`、`shared/security/actiontoken`）でも測り、検出 21、生き残り 24、not covered 81 だった。

- 10 演算子とも既定に入れない。
- `INTEGER_*` の生き残りの多くは、設定の値の定数（上限、時間切れ）と、`len(x) > 0` の `0` を `1` にする変異体で、後者は `CONDITIONALS_BOUNDARY` と同じ穴を示す。
- `BRANCH_IF` は既定の集合の変異体を 7 割増やし、not covered は既定の演算子の not covered と重なる。生き残りはエラーの経路を通らないテストの穴だが、`CONDITIONS_CONSTANT` と同じく、選んで使う。
- `RETURN_ERROR_NIL` は 6 割が not covered（テストが通らないエラーの経路）で、生き残りは少ない。
- `ERRORF_WRAP` は生き残りが届いた変異体の半分を超える。呼び出し元が `errors.Is` で連鎖を確かめないなら観測できないので、1 体ずつの見極めが要る。
- 数値のリテラルの箇所は、`const` の宣言と配列の長さの中なら、書き換える前に個別ビルドへ回す。呼び出しにすると定数でなくなるという誤りは、箇所の外（定数の式の先頭）に出て、どの箇所の誤りか特定できないためである。
`-only`、設定、無効化コメント、受理は、既定で無効な演算子の名前も受け付ける。
ビット演算子は短絡評価しないので、算術の演算子と同じく、両辺を先に評価する関数リテラルで埋め込む。
複合代入（`x op= v`）は、`v` を 1 回だけ評価して引数で渡し、有効な変異体に応じて元の演算子と変異後の演算子を切り替える関数呼び出しの文にする。対象の式 `x` は本文に写すので、その中の変異箇所は個別ビルドに回す。変異で値が変わるかは `x` にもよる（`x *= 1` と `x /= 1` など）ので、到達したら感染したとみなし、実行して確かめる側に倒す。
`break` と `continue` は同じ関数の中のループに作用するので関数リテラルで包めず、文を `if gamutActive == N { continue } else { break }` の 2 つの分岐にする。分岐にしたことでループの終端性が変わり `missing return` になる箇所は、書き換え後の型検査で個別ビルドに回る。ループの外の `continue` は型検査で構築不能になる。
`&&` と `||` は右辺を評価しないことがあるので、左辺だけを引数で渡し、右辺は関数リテラル `gamutR` の本文に 1 回だけ書いて、元の形でも変異後の形でも必要なときだけ呼ぶ。右辺の中の変異箇所はその本文の中に埋め込むので、到達の記録は元の短絡評価のとおりになる。変異で値が変わるかを知るには右辺を評価する必要があるので、到達したら感染したとみなす。
`true` と `false` は型情報で宇宙スコープの定数を指す識別子だけを選び、同じ名前の局所変数は変異しない。その場の型（名前付きの `bool` を含む）を返す関数呼び出しにし、`const` の宣言の中のように呼び出しを書けない箇所は、書き換え後の型検査で個別ビルドに回る。
`CONDITIONS_CONSTANT` の箇所は、条件の式を包む独自のノード（`mutant.ConditionSite`）で、式そのものの変異箇所とは別の箇所の鍵を持つ。範囲が式と同じなので、書き換えでは包む側を先にし、式の中の変異箇所は包む関数の中で書き換える。有効な変異体なら条件を評価せずに定数を返し、そうでなければ条件を評価して返す。`for` の条件を `true` にすると無限ループになり、時間切れを待つだけで遅いので、`false` だけにする。定数に置き換えると、条件でだけ使う変数が使われなくなり、構築不能になることがある。
`STATEMENT_REMOVE` は、文を消すと引数でだけ使う変数や import が使われなくなりコンパイルできないので、文を `if false { ... }` に置き換えて参照を残す。識別子の置き換え後の部分には固定の文字列を使い、引数を書き換えても識別子が変わらないようにする。schemata では `if gamutActive != N { ... }` にし、引数の中の変異箇所はその中で書き換える。
`RETURN_ZERO` は、本体の `{` の直後に `return *new(T1), *new(T2);` を差し込む。`T` はシグネチャの戻り値の型の字句を写すので、そのファイルの中で必ず書け、型パラメータにも使える。`error` も `nil` にする。`errors.New` などで `nil` でない値にするには import が要り、字句の置き換えだけで構築可能性を判定できなくなるためである。箇所は本体の `{` の 1 字を範囲にする独自のノード（`mutant.BodySite`）で、関数の入口の記録もそこで書く。`-since` では、本体の変更に交わるかで選ぶ。
`REMOVE_SELF_ASSIGNMENTS` は複合代入の規則に `=` への置き換えを足したもので、埋め込み方は `INVERT_ASSIGNMENTS` と同じである。
数値のリテラルと `ERRORF_WRAP` の書式は、その場の型を返す関数呼び出しにする（`BOOLEAN_LITERAL` と同じ）。型のない定数を `gamutMark` に渡すと既定の型になって外側の式の型が合わなくなるので、包めなければ個別ビルドに回す。
`BRANCH_*` は、本体の文の並び（ブロックの `{` と `}` の内側、`case` の `:` の後）を範囲にする独自のノード（`mutant.BranchSite`）で、`STATEMENT_REMOVE` と同じく `if false { ... }` で参照を残す。schemata では `if gamutActive != N { ... }` にし、本体の中の変異箇所はその中で書き換える。本体に入ったら感染したとみなす。本体を空にすると関数が終端しなくなる（`missing return`）変異体は、構築不能になる。識別子の置き換え後の部分には固定の文字列を使う。
`RETURN_ERROR_NIL` は、結果の式を包む独自のノード（`mutant.ErrorSite`）で、式の中の箇所とは別の箇所の鍵を持つ。置き換えは `func() error { if false { return <式> }; return nil }()` で、式でだけ使う import が使われなくならないよう参照を残す。schemata では、有効な変異体なら式を評価せずに `nil` を返し、そうでなければ式を `error` として受けて返す。`error` として受けるので、型付きの `nil` のポインタは元の `return` と同じく `nil` でない `error` になり、元の値が `nil` でなければ感染したとする。結果の型が `error` を満たす具体的な型の箇所は変異しない。
変異体は「ファイル、区間の先頭のバイト位置、元の文字列、置き換え後の文字列」で表し、構築可能性の判定と個別ビルドはこの置き換えだけで行う。
演算子の変異では、区間は演算子の字句 1 つで、文字列は字句と同じである。
字句で表せない変異（`!` の削除など）は、置き換え後の文字列を空などにして同じ表現に載せる。
識別子は置き換え後の文字列から作るので、演算子の変異の識別子は、表現を広げる前と変わらない。

## 変異体の識別子

識別子は `<モジュール相対のファイル>::<変異演算子>::<囲む関数>::<ハッシュ>` の形にする。
ハッシュは、囲む関数の名前、関数の中での構文木の経路（子の番号の列）、変異演算子、置き換え後の字句から作る。
行と列を含めないので、関係ない行を追加しても識別子は変わらない。
報告には人が読むための行と列も載せる。

## arid のコード

テストが観測しないことの多いコード（arid）の中では変異体を作らない。そこで生き残っても、テストを足す価値が小さく、仕分けの手間だけが増えるためである。
規則は呼び出し先の `types.Object` のパッケージと名前で判定し、字句の一致には頼らない。

| 規則 | 除くもの |
| --- | --- |
| 出力だけの呼び出し | `log`、`log/slog`、`expvar`、`go.opentelemetry.io/otel` とその下のパッケージの呼び出し。`Debug*`、`Info*`、`Warn*`、`Error*` のメソッドで、受け手の型の名前が `Log` を含むか、既知のロガーのパッケージ（zap、logrus、zerolog、logr、klog）のもの。書き込み先が `os.Stderr` の `fmt.Fprint*`。引数を変異せず、文の削除（`STATEMENT_REMOVE`）もしない |
| メッセージ | `panic`、`errors.New`、`fmt.Errorf` の引数。`panic` の文の削除は残す。`fmt.Errorf` の書式の `%w`（`ERRORF_WRAP`）と、`fmt.Errorf` の呼び出しを返す結果（`RETURN_ERROR_NIL`）は、メッセージではなくエラーの値を変えるので変異する。外側が arid（ログの引数の中など）なら変異しない |
| まとまりの本体 | 中身がすべて arid の文である分岐の本体は、空にしない（`BRANCH_*`） |
| 表示のメソッド | 引数なしで `string` を返す `String`、`GoString`、`Error` のメソッドの本体 |
| 時刻の算術 | `time.Now()` か `time.Since()` の呼び出しを被演算子に持つ算術 |
| まとまり | 中身がすべて出力だけの呼び出しの文である `if`（初期化の文がないもの）とブロック。条件を含めて全体を除く（Google の規則 `arid(n) = simple(n) ? expert(n) : children.every(arid)` の、文についての形） |

- 設定の `arid.calls`（`-arid-call`）は、`<パッケージ>.<名前>` か `<パッケージ>.<型>.<名前>` に当てる glob で、`*` は `/` と `.` にも当たる。`arid.packages`（`-arid-package`）は、そのパッケージとその下のパッケージの呼び出しを出力だけの呼び出しにする。
- `-no-arid` で、既定の規則も設定の規則も使わない。
- 除いた変異体の数を、報告の `gamut.counts.arid` と要約に出す。

2026-11-21、idmagic で規則を足す前と後を比べた（既定の演算子、`-no-cache`）。

| パッケージ | 変異体 | 生き残り | 除いた数 |
| --- | --- | --- | --- |
| `backend/shared/http/support_http` | 550 → 536 | 63 → 56 | 14 |
| `backend/shared/security/tokens_jose` | 335 → 333 | 28 → 28 | 2 |
| `backend/oauth2/internal/token/usecases` | 688 → 687 | 45 → 45 | 1 |
| `backend/provisioning/internal/client_scim` | 154 → 154 | 13 → 13 | 0 |

`support_http` で除いた生き残り 7 体は、ログの呼び出しの削除 6 体と、ログを出すだけの `if` の条件 1 体で、どれもテストが観測しないログだった。
除いたもののうち 3 体は検出されていた（エラーメッセージやログを確かめるテストがあった）。検出される変異体を除いても、直すべき生き残りの一覧は変わらない。
`usecases` の監査イベントの発行（`emit`）は、テストが確かめるべき副作用なので arid にしない。

## 無効化コメント

速さのための近道や防御のための分岐のように、変異しても観測できない箇所の変異体を、理由とともにその場で止める。

| コメント | 止める範囲 |
| --- | --- |
| `//gamut:ignore [TYPE,...] [-- 理由]`（同じ行にコードがある） | その行 |
| `//gamut:ignore ...`（単独の行） | 次の行 |
| `//gamut:ignore ...`（関数の宣言の Doc の中） | その関数全体 |
| `//gamut:ignore-start ...` から `//gamut:ignore-end` まで | その間の行。`end` がなければファイルの終わりまで |

- Go の指令コメントの慣習（`//go:`、`//nolint:`）に合わせ、`//` の直後に空白を置かない。`// gamut:ignore` は指令にならない。
- 演算子を省けばすべての演算子を止める。未知の演算子の名前は終了コード 1 で止める。綴りの誤りで、すべての演算子が止まったことに気づかなくなるためである。
- 理由のないコメント、対応しない `start` と `end`、未知の指令（`//gamut:` で始まる別の名前）は、警告して続ける。
- 範囲は `go/ast` のコメントの位置から求めた行で決め、構文木の付属情報には頼らない。関数全体だけは、Doc の付属先の宣言の範囲を使う。
- 止めた変異体は、列挙の直後に外し、型検査も実行もせず、数えない。残りの番号は 1 から振り直す。
- 報告では `Ignored` の状態にし、`statusReason` を `ignored by comment: <理由>` にして、`gamut.counts.ignored` に数える。判定しないので、内部の報告では判定した変異体と分けて持つ。
- `-mutant` で止めた変異体を指定したら、コメントの位置を示して終了コード 1 にする。

## 等価な変異体の受理

どの入力でも観測できない変異体（等価な変異体）は、テストを足しても検出できない。
ソースを変えずに理由を一か所にまとめるため、受理をモジュールのルートの `gamut.accepted.json` に、識別子と理由で記録する。

- `gamut accept -reason <理由> [-dir <ディレクトリ>] <識別子>...` で記録する。識別子は報告の `id` をそのまま使い、前方一致は受け付けない。記録は識別子の順に、項目ごとに行を分けて書く。
- 受理の記録を書くのは `gamut accept` だけで、判定の実行は書かない。対象のソースツリーへ書き込まない不変条件は、判定の実行についての約束であり、利用者が明示して記録するこのファイルは対象外とする。
- 受理した変異体は引き続き実行して判定を保つ。報告では `Ignored` の状態にし、`statusReason` を `accepted: <理由>`、判定した状態を `gamut.acceptedStatus` にする。`gamut.counts.total` と点数には含めず、`gamut.counts.accepted` に数える。要約の直す一覧には並べない。
- 判定したパッケージの受理のうち、テストが検出するようになったもの（`KILLED`、`TIMED OUT`）と、変異体がなくなったものを、報告の `gamut.staleAccepted` と要約に並べる。ほかのパッケージの受理は、そのパッケージを判定していないので、なくなったとはみなさない。`PENDING` の受理と、`-mutant` で選んだ実行の「なくなった」も判定しない。
- `gamut accept -prune [判定のフラグ] <パターン>...` は、判定してから、要らなくなった受理を消す。検出されるようになったかは判定しないと分からないので、ふだんの判定（キャッシュがあれば速い）を行う。`-prune` は判定のフラグと区別するため、先頭でだけ受け付ける。
- 識別子は位置に依存しないので、関係ない編集では受理が外れない。囲む宣言の中の構文木の経路が変わると識別子も変わり、「なくなった」として挙がるので、新しい識別子を受理し直す。
- 受理の記録は、変更のない再実行の入力の指紋に入れる。受理を変えれば報告が変わるためである。判定の鍵には入れない。

## 等価な変異体の自動検出

`-detect-equivalent` は、生き残った変異体（`LIVED`）ごとに、変異を当てたパッケージをコンパイルし、元のコンパイル結果と比べる。
同じなら、どの入力でも観測できないので `EQUIVALENT`（`reason: same machine code`）にする。
Go のコンパイラは定数の畳み込みと不要な分岐の除去を行うので、`x * 1` を `x / 1` にする変異体のようなものを、テストを実行せずに見分けられる。

- コンパイルは `go tool compile -S -dwarf=false` を直接呼び、読み込みで得た依存のエクスポートデータから `-importcfg` を作る。`go build` を通さないので、変異体ごとのコンパイル結果を共有のビルドキャッシュへ書かない。
- 比べるのはパッケージ全体のアセンブリで、命令に付く位置の注記（`(file.go:12)`）を除く。変異は字句 1 つの置き換えなので、ほかの関数は変わらない。囲む関数が呼び出し元にインライン化されていれば、呼び出し元の違いも捉える。ファイルは一時ディレクトリに写し、`-trimpath` で、元と変異体のパスの違いを消す。
- 変異体がコンパイルできなければ、等価ではないとする。
- 埋め込みファイルやアセンブリのファイルを持つパッケージは、`-embedcfg` や `-symabis` が要るので比べず、警告する。
- 報告では `Ignored` の状態にし、`statusReason` を `equivalent: same machine code` にする。`gamut.counts.total` と点数には含めず、`gamut.counts.equivalent` に数える。
- 比較の結果は、構築可能性と同じ鍵（囲む宣言、依存、外の依存）でキャッシュに記録し、鍵の変わらない変異体はコンパイルし直さない。判定の記録は `LIVED` のまま残るので、フラグを外せば `LIVED` に戻る。
- 既定では無効にする。生き残り 1 体につきパッケージを 1 回コンパイルするためである。

2026-11-21、idmagic の `backend/oauth2/internal/token/usecases` では、生き残り 29 体のコンパイルと比較に 2.2 秒かかり、共有ビルドキャッシュは増えず、等価と判定された変異体は 0 体だった。
生き残りは境界の比較や否定のように、コードとして違いが残る変異だった。

## 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| 文字列のリテラルを変異する | ログとエラー文の変異体が多く、そのほとんどはテストが観測しないので、仕分けの負担が大きい |
| 等価な変異体の検出に `go build -gcflags=<pkg>=-S` を使う | 生き残り 1 体ごとのコンパイル結果が共有のビルドキャッシュにたまる。一時的な `GOCACHE` にすると、依存をすべてビルドし直すので遅い。`go tool compile` を直接呼べば、どちらも避けられる |
