# gamut の設計

gamut は Go のパッケージに機械的な変異を加え、そのパッケージのテストが変異を検出できるかを調べるミューテーションテストツールである。
この文書は、実行の流れ、変異体の表現、schemata の書き換え、判定と報告の形式、採らなかった案を定める。

## 目的

- **速い**：変異体ごとにパッケージをコンパイルし直さない。全変異体を 1 回のビルドに埋め込み、どれを有効にするかを実行時に選ぶ（mutant schemata）。
- **ビルドキャッシュを汚さない**：変異体ごとのビルド結果を共有の Go ビルドキャッシュへ書き込まない。
- **生き残りを仕分けやすくする**：生き残った変異体を、テストが到達しなかったもの、到達したが値が変わらなかったもの、値は変わったが表明が見ていないものに分ける。
- **単純である**：Go の標準ライブラリと `go` コマンドだけに依存する。

## 実行の流れ

1. **読み込み**：引数のパターン（パッケージディレクトリか `<ディレクトリ>/...`）を絶対パスにし、最初のパターンのディレクトリで `go list -json -export -deps <パターン>...` を 1 回だけ実行して、対象パッケージのファイルと、依存パッケージのエクスポートデータの場所を得る。ビルドタグ（`-tags`）は `go list` と `go test -c` の両方に渡す。対象のファイルは `go list` の `GoFiles` に従い、ビルドの条件を自前で評価しない。対象のファイルを `go/parser` で読み、`go/types` で型を検査する。
2. **列挙**：型情報を使って変異箇所を列挙する。ログ出力の呼び出し（`log`、`log/slog` のパッケージ関数とメソッド）の引数の中は変異しない。生成されたファイル（`// Code generated ... DO NOT EDIT.`）は対象にしない。
3. **構築可能性の判定**：変異体ごとに、演算子の字句だけを置き換えたファイルでパッケージを `go/types` で検査し直す。通らない変異体を `NOT VIABLE` とする。
4. **schemata の書き換え**：構築可能な変異体を埋め込んだソースを一時ディレクトリに作り、書き換え後のパッケージを `go/types` で検査する。エラーを出した箇所は schemata から外し（後述の「個別ビルド」へ回す）、エラーがなくなるまで繰り返す。
5. **ビルド**：パッケージごとに `go test -c -overlay` でテストバイナリを 1 回だけビルドする。元のソースは書き換えない。
6. **被覆の記録**：`-test.list` でテストの一覧を得て、変異を無効にしたまま、トップレベルのテストを 1 件ずつ別のプロセスで実行する。各プロセスは、到達した変異箇所と、変異後の値が元の値と異なった変異体を記録する。ここで失敗するテストがあれば、基準が壊れているので、そのテストの出力を見せて終了コード 4 で中断する。`-test.list` 自体の失敗（`TestMain` の準備の失敗など）も同じに扱う。
7. **自己検査（forced fail）**：到達の記録があるテストのうち最も短い 1 件を、`GAMUT_MUTANT=-1` で 1 回だけ実行し、失敗することを確かめる。詳しくは「変異の届き方の自己検査」で述べる。
8. **再利用**：実行が要る変異体のうち、前回の判定の鍵が今と一致するものは、実行せずにキャッシュの判定を使う。詳しくは「判定の再利用」で述べる。
9. **実行**：変異体ごとに、到達したテストだけを短い順に `-test.run` で指定し、`-test.failfast` を付けてバイナリを実行する。どの変異体を有効にするかは環境変数 `GAMUT_MUTANT` で渡す。
10. **報告**：判定を JSON に書き、生き残りを分類ごとに標準出力へ並べる。

手順 4 から 7 はパッケージごとに行い、手順 8 と 9 は全パッケージの変異体を 1 つの作業の列にする。詳しくは「複数のパッケージ」で述べる。
変異体ごとにプロセスを分けるので、無限ループ、`panic`、パッケージ変数の汚染が他の変異体に漏れない。
時間切れの上限は、選んだテストの被覆記録時の実行時間の合計に係数を掛け、下限を足して決める。

### 複数のパッケージ

- `go list` の出力のうち、`DepOnly` でなく、テスト以外の Go ファイルを持つパッケージを対象にする。テストファイルしか持たないパッケージは変異の対象がないので外す。補助ファイルのために列挙する標準パッケージも対象にしない。
- 対象のパッケージは同じモジュールに属することを求める。報告の `files[].path` と変異体の識別子はモジュール相対のパスなので、モジュールをまたぐと区別できない。
- 全パッケージで 1 つの `token.FileSet` と、エクスポートデータの importer を共有する。gc の importer は並行に使えないので mutex で守り、読んだ `types.Package` は全パッケージで再利用する。
- 対象パッケージ A が対象パッケージ B を import するとき、A の型検査は B の書き換え前のエクスポートデータを使い、A のテストバイナリは B の書き換え前の版にリンクされる。B の変異は B のテストだけで判定し、A のテストでは検出を試さない。逆依存のテストでの検出は統合モードで扱う。
- schemata の書き換えとビルドとテストの一覧は、パッケージごとにワーカー数まで並列に行う。被覆の記録と変異体の実行は、全パッケージの分を 1 つの作業の列にまとめ、同じワーカーで回す。テストのプロセスの数はパッケージの数によらずワーカー数までになる。
- 変異体の番号（`GAMUT_MUTANT`）はパッケージごとに 1 から振る。テストバイナリはパッケージごとに別なので衝突しない。
- テストファイルを持たないパッケージは、ビルドせずに構築可能な変異体をすべて `NOT COVERED` とする。構築可能な変異体がないパッケージもビルドしない。
- どれかのパッケージで基準のテストか自己検査が失敗したら、どのパッケージも判定せずに止める。一部のパッケージだけの報告は、全体の判定と見分けにくいためである。

### テストバイナリの起動

- テストバイナリの実行（一覧、被覆の記録、自己検査、変異体の実行）にはすべて、利用者のテストのフラグ（`-test-flags`）を先に、gamut が実行ごとに決めるフラグを後に渡す。`-short` のような接頭辞なしの testing のフラグには `-test.` を補い、テストが自分で定義したフラグはそのまま渡す。gamut が決める `run`、`count`、`failfast`、`list`、`paniconexit0` は受け付けない。
- Unix ではテストバイナリを新しいプロセスグループで起動し（`Setpgid`）、時間切れと取り消しではグループ全体へ `SIGKILL` を送る。テストが起動した子プロセスが残って CPU を使い続けたり、出力の管を握って待ちを延ばしたりしないためである。Windows ではテストバイナリだけを止める。止めた後に出力の管が閉じるのを待つ時間は 1 秒までとする（`WaitDelay`）。
- 到達と感染の記録は、変異箇所ごとの `atomic.Bool` と、ファイルへの追記を守る 1 つの mutex で行う。`t.Parallel` のテストや多数のゴルーチンが同じプロセスで変異箇所を通っても記録は欠けない。

### 時間切れの既定値

既定は係数 5、下限 2 秒である。
2026-11-20 に Apple Silicon の macOS で fixture のテストバイナリを短いテスト 1 件で 300 回起動したところ、起動から終了までは中央値 3 ms、99 パーセンタイル 8 ms、最大 264 ms（最初の 1 回）だった。
並列数を 8 にしても中央値 5 ms、最大 9 ms だった。
短いテストでの揺らぎは下限の 2 秒に比べて十分小さいので、既定値は変えない。
被覆の記録の実行時間は、プロセスの起動と記録の処理を含むので、変異体の実行より長めに出る。上限は安全側に倒れる。

## 判定の再利用

変更のない再実行や、1 関数を変えた後の再実行で、変わらない変異体を実行し直さないため、変異体ごとの判定を鍵とともにキャッシュファイルに保存する。
被覆の記録と自己検査は毎回行う（被覆の記録の省略は [005](../work-items/005-incremental-coverage.md) で扱う）。

- 保存先は `-cache`（既定は作業ディレクトリの `.gamut/cache.json`）で、`-no-cache` で読みも書きもしない。対象のソースツリーへ書き込まないため、モジュールのルートではなく作業ディレクトリを既定にする。
- 主キーは変異体の識別子である。識別子は行と列に依存しないので、位置を補正せずにそのまま引ける。同じ識別子を持つ変異体が 2 体以上あれば（同じ形の `init` が 2 つあるときなど）、それらは再利用しない。
- キャッシュを使うのは、実行が要る変異体（schemata で感染した変異体と個別ビルドの変異体）だけである。`NOT COVERED`、`LIVED`（`not infected`）、型検査による `NOT VIABLE` は、毎回の読み込みと被覆の記録から実行せずに決まる。

### 鍵

どの鍵も、位置とコメントを除いた構文木か、ファイルの中身から作る SHA-256 の先頭 64 ビットである。

| 鍵 | 中身 |
| --- | --- |
| 囲む宣言 | 変異箇所を含む最上位の宣言の構文木。位置、コメント、空白を含めない |
| 依存 | 囲む宣言が `go/types` の参照（`Info.Uses`）で推移的に参照する、同じパッケージの宣言（生成ファイルを含む）の構文木。インターフェースのメソッドの呼び出しは、パッケージの同名のメソッドすべてに届くとみなす。`init` はすべての宣言の依存にする |
| 外の依存 | `go list -deps -test` が返すテストバイナリの依存のうち、メインモジュール（ワークスペースを含む）か版のない replace の先にあるパッケージの Go ファイルと埋め込みファイル、対象パッケージの埋め込みファイル、対象パッケージの `testdata` の下のファイル。パッケージごとに 1 つ |
| テスト | トップレベルのテストの関数と、それが推移的に参照するテストファイルの宣言の構文木。`TestMain` と `init` はすべてのテストに含める。`Example` は期待する出力を書いたコメントも含める |
| 環境 | `go env` の `GOVERSION`、`GOOS`、`GOARCH`、`GOFLAGS`、`GOEXPERIMENT`、`CGO_ENABLED`、`GOWORK`、gamut の実行ファイルの中身、`go.mod`、`go.sum`、`go.work`、変異演算子の集合、ビルドタグ、テストのフラグ、時間切れの係数と下限。ファイル全体に 1 つで、違えば記録をすべて捨てる |

- 依存は宣言の粒度、外の依存はパッケージの粒度にして、粗い側に倒す。
- テストファイルは型検査せず、識別子の名前の一致で参照を近似する。テストだけが import するパッケージのエクスポートデータを読み込みで作っていないためである。同名の局所変数も参照とみなすので、鍵は粗い側に倒れる。
- gamut の版は、開発中の版では文字列が変わらないので、実行ファイルの中身で区別する。

### 再利用の規則

| 状態 | 再利用する条件（どれも、囲む宣言と判定の方式が変わらないことを前提にする） |
| --- | --- |
| `KILLED` | 依存と外の依存が変わらず、検出したテストが変わらず、今回もそのテストを実行する（schemata なら感染する）。検出したテストが分からなければ `LIVED` と同じ規則にする |
| `LIVED`（`not detected`） | 依存と外の依存が変わらず、到達したテストと実行するテストの集合が前回と同じで、そのどのテストも変わらない |
| `TIMED OUT` | 依存と外の依存が変わらない |
| `NOT VIABLE`（個別ビルドでコンパイラが拒んだもの） | 依存と外の依存が変わらない |

被覆の記録を毎回やり直すので、到達と感染はいつも今のソースのものである。
テストの鍵は、テストが呼ぶパッケージの宣言を含めない。
そのため、変異体の宣言が参照せずテストだけが呼ぶ宣言を変え、値は変わるが検出されるかどうかだけが変わる場合は捉えない。
到達と感染が変われば集合の比較で捉える。
`fmt.Stringer` のような、参照の形を取らない呼び出しも依存に入らない。
疑わしいときは `-no-cache` で実行する。

### 書き込み

- 実行が 1 体終わるたびに判定を記録し、終了時に書く。取り消し（`SIGINT`、`SIGTERM`）や基準のテストの失敗で止まったときも、それまでの判定を書く。
- 取り消しの後に終わった実行は記録しない。止められたテストは失敗に見え、`KILLED` と区別できないためである。
- 同じディレクトリの一時ファイルに書いてから改名する。途中で止まっても前のファイルは壊れない。
- 今回判定するパッケージの記録のうち、今回列挙されなかった変異体のものは捨てる。ほかのパッケージの記録は残すので、パッケージを分けて実行しても互いの記録を消さない。1 つのファイルは 1 つのモジュールの記録を持つ（環境の鍵が `go.mod` を含むため）。
- 報告の各変異体には、再利用したかを `cached` に書く。

## 変異演算子

| 名前 | 対象 | 置き換え |
| --- | --- | --- |
| `ARITHMETIC_BASE` | 二項の `+`、`-`、`*`、`/`、`%` | `+`↔`-`、`*`↔`/`、`%`→`*` |
| `CONDITIONALS_BOUNDARY` | `<`、`<=`、`>`、`>=` | `<`↔`<=`、`>`↔`>=` |
| `CONDITIONALS_NEGATION` | `==`、`!=`、`<`、`<=`、`>`、`>=` | `==`↔`!=`、`<`↔`>=`、`>`↔`<=` |
| `INCREMENT_DECREMENT` | `++`、`--` の文 | `++`↔`--` |
| `INVERT_NEGATIVES` | 単項の `-` | `+` |

名前と置き換えは Gremlins と gomutants に合わせる。
どの変異も、演算子の字句 1 つを別の字句に置き換える。
そのため、変異体は「ファイル、字句のバイト位置、元の字句、置き換え後の字句」で表せ、構築可能性の判定と個別ビルドはこの置き換えだけで行える。

## 変異体の識別子

識別子は `<モジュール相対のファイル>::<変異演算子>::<囲む関数>::<ハッシュ>` の形にする。
ハッシュは、囲む関数の名前、関数の中での構文木の経路（子の番号の列）、変異演算子、置き換え後の字句から作る。
行と列を含めないので、関係ない行を追加しても識別子は変わらない。
報告には人が読むための行と列も載せる。

## schemata の書き換え

変異箇所を持つ式を、引数で被演算子を受け取る即時に呼ぶ関数リテラルで包む。

```go
// 元: if a.Count(x) < limit {
if func(l int, r int) bool {
	if gamutCovering {
		gamutHit(4)
		if (l <= r) != (l < r) { gamutInfect(11) }
		if (l >= r) != (l < r) { gamutInfect(12) }
	}
	switch gamutActive {
	case 11:
		return l <= r
	case 12:
		return l >= r
	}
	return l < r
}(a.Count(x), limit) {
```

- 被演算子は引数として 1 回だけ、左から右へ評価する。元の式と同じく、有効にした変異の演算だけを計算する。
- 定数の被演算子と型のない `nil` は、引数にせず本文へそのまま埋め込む。型推論と定数の扱いを元の式と同じにするためである。
- 引数の型は `go/types` の型を、そのファイルの import 名で書く。書けない型（import されていないパッケージの型、別パッケージの非公開の型）を持つ箇所は schemata にしない。
- 入れ子の変異箇所は、内側から書き換えた字句を外側の引数に入れる。被演算子を 1 回しか書かないので、入れ子が深くても字句は増えない。
- `x++` は `func() { if gamutActive == 7 { x-- } else { x++ } }()` という式文に置き換える。`for` の後処理文にも置ける。
- 選択の変数と被覆の記録の関数は、overlay で足す 1 ファイル（`gamut_schemata.go`）に置く。対象パッケージに同じ名前があれば中断する。

書き換え後のパッケージが型検査を通らない箇所（たとえば名前付きの `bool` 型への代入、定数の文脈）は、エラーの位置を含む最も内側の箇所から順に schemata から外す。
外した変異体は、演算子の字句だけを置き換えたファイルを overlay で渡す個別ビルドで判定する。
個別ビルドの変異体は到達の記録を持たないので、全テストを実行する。

### 感染の記録

被覆の記録の実行では、各変異体の変異後の値を計算し、元の値と比べる。
異なれば、その変異体はそのテストで「感染した」と記録する。
変異後の演算が `panic` しうる整数の除算は、除数が 0 なら比べずに感染とみなす。
到達したが一度も感染しなかった変異体は、実行せずに生き残り（理由 `not infected`）と判定する。
この判定は weak mutation の考え方による。値が変わらない以上、どのテストも失敗しえない。

## 変異の届き方の自己検査

schemata の書き換えがテストバイナリに入っていない、または `GAMUT_MUTANT` が子プロセスへ渡っていないと、すべての変異体が `LIVED` か `NOT COVERED` になり、テストの弱さと見分けが付かない。
そこで判定の前に、変異を強制的に失敗させる実行（forced fail）で、変異がテストに届くことを確かめる。

- 補助ファイルの `gamutHit` は、`gamutActive` が `-1`（`schemata.ForcedFail`）なら `panic("gamut: forced fail")` する。各変異箇所の書き換えには字句を足さない。
- `gamutHit` は被覆の記録中にだけ呼ばれるので、検査は `GAMUT_COVER` と `GAMUT_MUTANT=-1` を両方渡して実行する。
- 実行するのは、到達の記録があるテストのうち最も短い 1 件だけである。到達が記録された以上、同じバイナリで `panic` しないなら選択の変数が読まれていない。全テストを実行する必要はない。
- テストが通るか時間切れになったら、判定せずに終了コード 4 で止める。到達のあるテストが 1 件もなければ、検査を飛ばしたことを警告して続ける。
- 個別ビルドの変異体は変異を直接書き込むので、届かない経路がなく、検査しない。
- 対象のコードが `recover` で `panic` を握りつぶすと、選択が届いていても検査が失敗しうる。その場合のエラーメッセージはこの可能性も挙げる。

## 判定と報告

| 状態 | 意味 |
| --- | --- |
| `KILLED` | 選んだテストのどれかが失敗した |
| `LIVED` | 生き残った。`reason` が `not infected`（到達したが値が変わらない）か `not detected`（値は変わったが失敗しない） |
| `NOT COVERED` | どのテストも到達しなかった |
| `NOT VIABLE` | 変異後のパッケージが型検査を通らない |
| `TIMED OUT` | 時間切れの上限を超えた |

JSON の報告は gomutants と同じ `files[].mutations[]` の形にし、各要素に `id`、`type`、`status`、`line`、`column`、`original`、`replacement` を持たせる。
gamut は加えて `reason`、`tests`（到達したテスト）、`killed_by`、`mode`（`schemata` か `standalone`）、`cached`（判定をキャッシュから再利用したか）を持たせる。
`files[].path` はモジュール相対のパスである。
最上位の `package` は、1 パッケージならその import パス、複数なら引数に指定したパターンを空白でつないだものにし、判定したパッケージの import パスを `packages` に並べる。
gomutants の報告を読む既存の検査は、そのまま gamut の報告を読める。

終了コードは、0 が判定を終えたこと、1 が読み込みやビルドなどの誤り、2 が引数の誤り、4 が基準のテストの失敗か自己検査の失敗で判定しなかったことを表す。

### 段階

- **段階 1（済み）**：schemata、`go/types` による構築不能の判定、式単位の被覆と感染、生き残りの 3 分類、位置に依存しない識別子、gomutants 互換の JSON。

### Go ならではの強み

Go の性質を使う方向を挙げる。

- **型による確実な構築可能性**：`go/types` は Go のコンパイラと同じ規則で検査するので、構築不能の判定に漏れがほぼない。
- **静的な被覆の補助**：Go の呼び出しは静的に解決しやすいので、`golang.org/x/tools` を使わずとも、`go/types` の参照から変更の影響を受けるテストを絞れる。
- **プロセスの起動が安い**：テストバイナリは単一の実行ファイルなので、変異体ごとにプロセスを分けても速度は十分で、変異体どうしを確実に隔離できる。

## 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| 変異体ごとに overlay でビルドする | 変異体の数だけコンパイルとリンクを繰り返し、結果が共有のビルドキャッシュにたまる。この方式では idmagic の 563 体のパッケージで 352 秒、2.6 GiB だった |
| 元の値と変異後の値を両方計算する選択関数（`sel(id, a+b, a-b)`）で包む | 副作用のある被演算子を 2 回評価し、元のプログラムにない `panic`（0 除算）を起こす |
| 被演算子を関数リテラルの本文に 2 回書く | 入れ子の変異箇所で字句が指数的に増える |
| 複数の変異体を 1 プロセスで順に有効にする | 変異体どうしでパッケージの状態が漏れる。並列に実行すると、テストの失敗による早期の打ち切りも効きにくくなる |
| `golang.org/x/tools/go/packages` で読み込む | 依存が増える。`go list -export` とエクスポートデータの importer で足りる |
| パッケージ単位で判定をキャッシュする | import 先の変更を追えず、古い判定を返しうる。1 関数の変更でパッケージの全変異体を実行し直す |
| 判定と一緒に元のソースを保存し、差分で位置を補正する | 報告が肥大し、依存の変更を捉えない。識別子が位置に依存しないので補正は要らない |
| テストの鍵に、テストが呼ぶパッケージの宣言を含める | 1 関数を変えると、それを呼ぶテストが到達する別の宣言の変異体まで実行し直す。到達と感染の変化は毎回の被覆の記録で捉えられる |
